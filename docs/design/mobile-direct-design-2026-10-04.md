# Veil Design 01 — личные чаты на телефоне

Дата: 2026-10-04. Это рабочее предложение интерфейса и отдельный offline APK, не новый доверенный клиент и не завершение backend roadmap.

## Цель и границы

Получить удобный способ обсуждать мобильный интерфейс на настоящем телефоне: открыть приложение без регистрации и Access Pass, попробовать навигацию и ввод, сделать скриншоты. Отдельный Android application ID `io.veil.mobile.designpreview` позволяет установить **Veil Design** рядом с Veil/Veil Tester. У preview нет сетевого разрешения, собственного входа в аккаунт, enrollment links, Rust-библиотеки Veil и native Veil bridges. Данные — вымышленные fixtures в памяти процесса. Сворачивание не обязательно уничтожает процесс; перезапуск процесса возвращает исходный набор.

Скриншоты разрешены только в отдельной DesignActivity. Production/MainActivity и RecoveryActivity не изменяются: нельзя отключать их защиту ради дизайн-работы. Секреты, ключи, Access Pass, настоящие аккаунты и история не нужны для макета и не импортируются в него.

Пользователь сообщил: на другом телефоне со старым APK простой обмен с ПК работал; затем произошёл сбой при действии с ответом на ПК. Это полезное свидетельство ручного теста, но не установленная причина ошибки. Уточнить обычная отправка это была или «ответить на сообщение», собрать безопасный код ошибки и время отдельно. Не смешивать этот сбой с дизайном и не считать его исправленным новым preview APK.

## Информационная архитектура

Четыре равноправных направления нижней навигации: **Чаты · Группы · Пространства · Настройки**. Внутри личного разговора нижняя навигация скрыта: остаются собеседник, история и поле ввода. Back возвращает в тот список и поиск, из которого открыли разговор; черновик не теряется. Панели профиля и сценариев закрываются раньше, чем сам чат.

Группа — самостоятельный разговор нескольких участников. Пространство — контейнер связанных каналов, участников и ролей. Это разные разделы; нельзя рисовать пространство как большой Direct. Сейчас обе вкладки объясняют назначение и показывают, что раздел недоступен. Кнопок создания, вступления, голосовой связи и управления ролями пока нет.

Такой выбор соответствует Android guidance: основные направления доступны снизу на компактном экране; вторичные фильтры располагаются внутри раздела. При будущей поддержке планшета основной навигации потребуется rail и отдельная master/detail-компоновка, а не растянутая телефонная полоса. [Android: layouts and navigation](https://developer.android.com/design/ui/mobile/guides/layout-and-content/layout-and-nav-patterns).

## Личный чат: что должно ощущаться естественным

| Экран / действие | Поведение Design 01 | При подключении реального клиента |
|---|---|---|
| Список | Имя, короткий последний текст, время, локальные непрочитанные, закреплённые fixtures; черновик имеет приоритет над preview текста | Только native directory/timeline metadata; не вычислять доменный порядок из UI и не выдавать fixtures за серверные сведения |
| Поиск | Локальный поиск по имени и username среди вымышленных контактов | Разделить поиск существующих чатов и native exact-username поиск новых контактов; локальный demo search не заменяет server API |
| Новый разговор | Отдельное состояние списка демо-контактов, включая контакт без истории | Нажатие запускает native authenticated create Direct; сначала pending/error, затем навигация по подтверждённому DTO |
| История | Лево/право, спокойные пузырьки, многострочный текст, явное время; не переключать экран при вводе | Стабильный native UI ID, bounded native window и пагинация; timestamp отсутствует — UI не придумывает его |
| Прокрутка | Следовать новым локальным строкам в конце; изменение размера не должно сбрасывать чтение старой истории | Новые события не уводят читателя вниз; добавить кнопку новых сообщений и восстановление позиции по native anchor |
| Ввод | Многострочный controlled input, активная отправка только при непустом тексте, черновик на каждый чат | Native command/outbox подтверждает принятие; JS не создаёт envelope, ID, очередь или вторую SQLCipher-историю |
| Ошибка | Текст остаётся в строке сообщения; «Повторить» меняет ту же demo-строку без дубля | Повтор только по native eligibility и native outbox identity. Не повторять сообщение со статусом unknown |
| Профиль | Имя/username и пояснение, что личность не сравнивалась; никаких настоящих ключей или QR | Отдельно account ID / origin / continuity и native результат сравнения; имя, аватар и online не являются доказательством |
| Ответ / вложение | Информационная панель; действий reply/edit/delete/upload нет | Добавлять после реализации соответствующего контрактного перехода, тестов совместимости и проекции mobile DTO |

## Состояния без ложных обещаний

В Настройках и через `…` внутри чата доступны сценарии: обычный, offline, ошибка, неизвестный статус, изменение ключа. Они воздействуют на следующие **локальные demo-сообщения**, не переписывают уже показанную историю и не имитируют настоящий сервер.

| Данные реального mobile contract | Проектируемый UI | Чего не подразумевает |
|---|---|---|
| `sending` | Индикатор отправки; «В очереди» только если native подтверждает именно очередь | Не серверное подтверждение |
| `sent` | Один check / «Отправлено» | Не «доставлено» и не «прочитано» |
| `failed` | Явная ошибка и доступный по контракту повтор | Не самостоятельный новый envelope от JS |
| `unknown` | «Статус неизвестен» без повтора | Нельзя считать ошибкой и слепо отправлять ещё раз |
| `not_compared` | Нейтральное «Личность не сравнивалась» | Не красная авария и не доказанное доверие |
| `verified_on_this_device` | Подтверждение на этом устройстве после native проверки | Не глобальная проверка всех устройств |
| `identity_changed` | Заметный поясняющий блок и закрытая отправка, черновик сохраняется | Нельзя «продолжить всё равно» обходом native boundary |

Точки входа: `veil-mobile/src/native/runtime.ts` (Direct DTO), `veil-ffi/src/lib.rs` (delivery projection, unsupported reply/attachments/TTL), `veil-client/src/direct.rs` (directory only Direct). FFI сейчас сводит sent/delivered/read к одному mobile `sent`; UI не имеет оснований показывать blue double-check. Reply присутствует в некоторых нижних моделях, но текущая mobile projection его не принимает. Групповые разговоры также не приходят через существующий Direct directory.

## Визуальная система

Спокойная тёмная основа, приглушённые поверхности, фиолетовый акцент Veil только для выбора и основной отправки. Светлая тема нужна сразу для сравнения и проверки читабельности. Система шрифта Android, основной текст сообщения 16sp, отдельные компактные метаданные; никаких обязательных сетевых шрифтов и внешних аватаров. Начальный экран явно маркирован DESIGN; в чате указано «демо», есть пояснение об offline переписке.

Касаемые кнопки и фильтры имеют минимум 48dp, сообщения раскрываются также обычным нажатием, не только удержанием. Статусы выражены текстом и иконкой, а не одним цветом. [Android touch target guidance](https://support.google.com/accessibility/android/answer/7101858?hl=en). Поле ввода учитывает safe area и Android `adjustResize`; не накладывать одновременно две независимые компенсации клавиатуры. На iOS предусмотрен KeyboardAvoidingView, но iOS-сборка в этот этап не входит. [React Native 0.79 KeyboardAvoidingView](https://reactnative.dev/docs/0.79/keyboardavoidingview).

Используется уже лицензированный подход к controlled composer из нашего presentation port Rocket.Chat.ReactNative 4.77.0, pinned commit `0a7df3d82a2e9d20e37f9ec5651fd3c74b98ab36`. Notice находится в About, исходная MIT license и источник — в `veil-mobile/third-party/rocket-chat-reactnative`. [Pinned upstream](https://github.com/RocketChat/Rocket.Chat.ReactNative/tree/0a7df3d82a2e9d20e37f9ec5651fd3c74b98ab36), [license](https://github.com/RocketChat/Rocket.Chat.ReactNative/blob/0a7df3d82a2e9d20e37f9ec5651fd3c74b98ab36/LICENSE).

Preview не является полным frontend Rocket.Chat. Пузырьки, навигация, demo-controller и палитра — дальнейшая работа над Veil. Не переносим Rocket transport, Redux/auth, WatermelonDB, push и crypto. Существующие `ChatIsland`, `IdentityIslandSheet` и старый `DesignPreviewHomeScreen` связаны с native runtime/store/camera и для отдельного offline entry не подходят.

## Порядок дальнейшей работы

1. **Телефонная оценка Design 01.** Скриншоты списка, открытого чата с клавиатурой, длинного текста, светлой темы и ошибки. Пройти сценарии ниже. По обратной связи поправить размеры, плотность, контраст, позиции и формулировки.
2. **Чистые presentation-компоненты.** После выбора дизайна выделить ChatListItem, DirectHeader, MessageBody, DeliveryLabel, Composer, IdentitySummary и EmptyState с narrow props. Fixtures/controller оставить только в preview entry. Production adapter получает native DTO, команды и lifecycle; дизайн-компоненты не импортируют native authority.
3. **Настоящие Direct.** Подключать по одному переходу: directory → exact username → create → history → native draft/outbox → retry → identity comparison. Каждый этап проверять ПК ↔ Android; не переносить demo unread/pinning/queue в production без native поддержки. Отдельно исправить и проверить обнаруженный сбой на ПК при ответе.
4. **Группы и пространства.** Сначала native contracts и OpenMLS переходы, затем отдельные presenters и acceptance. Общая оболочка навигации уже предусмотрена; crypto Direct не становится fallback для группы.

## Ручная проверка на телефоне

Установить отдельный Veil Design, не удаляя Veil/Veil Tester и не очищая их данные. Билет не нужен. Первая версия содержит только вымышленные контакты.

1. Открыть Анну, написать черновик, вернуться в список, снова открыть — черновик остался. Написать другой черновик Максиму — они независимы.
2. Отправить локальный текст, длинный абзац, emoji и переносы строк. Проверить экран с открытой клавиатурой и жестовой навигацией; поле ввода и отправка доступны.
3. Через `…` выбрать ошибку, добавить сообщение, перейти на обычный сценарий и нажать «Повторить» — одна строка, без дубля. При unknown кнопки повтора нет.
4. Выбрать «Ключ изменился» при существующем черновике: отправка недоступна, черновик не исчез. Профиль не обещает реальную проверку.
5. Проверить поиск, очистку, непрочитанные, новый чат с Никитой без истории, обе темы и зарезервированные вкладки.
6. Сделать скриншоты. Увеличить системный размер шрифта; проверить перенос названий вкладок, доступность кнопок и TalkBack. Повернуть телефон и проверить safe area. Перезапустить процесс — исходные fixtures восстановились.

Host unit/render tests не подтверждают работу клавиатуры, жестов и фактического захвата экрана на устройстве. Результаты сборки и проверки фактического APK записываются отдельно; физическая проверка остаётся ручной.
